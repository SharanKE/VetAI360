# VetAI 360 — Cloud Deployment Guide

Deploy VetAI 360 to the cloud with **MongoDB Atlas** (database) and **Render.com** (hosting). This guide walks through every step.

## Architecture (production)

```
┌─────────────────┐     HTTPS      ┌─────────────────┐
│  vetai360-web   │ ─────────────► │  vetai360-api   │
│  (React static) │                │  (Node + Socket)│
└─────────────────┘                └────────┬────────┘
                                            │
                         ┌──────────────────┼──────────────────┐
                         ▼                  ▼                  ▼
                 ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
                 │ MongoDB Atlas│   │ vetai360-ml  │   │  Socket.IO   │
                 │   (M0 free)  │   │   (Flask)    │   │  (real-time) │
                 └──────────────┘   └──────────────┘   └──────────────┘
```

| Service | Host | Purpose |
|---------|------|---------|
| Frontend | Render static site | React dashboard |
| Backend API | Render web service (Docker) | REST + Socket.IO |
| ML service | Render web service (Docker) | AI diagnosis |
| Database | MongoDB Atlas M0 (free) | Production data |

## Part 1 — MongoDB Atlas setup

### 1. Create a free cluster

1. Go to [https://cloud.mongodb.com](https://cloud.mongodb.com) and sign up (free).
2. Click **Build a Database** → choose **M0 FREE** (Shared).
3. Pick a cloud provider & region close to your users (e.g. AWS Mumbai `ap-south-1`).
4. Cluster name: `vetai360-cluster` → **Create**.

### 2. Create a database user

1. In Atlas → **Database Access** → **Add New Database User**.
2. Authentication: **Password**.
3. Username: `vetai360_user`
4. Password: generate a strong password and **save it**.
5. Privileges: **Read and write to any database**.
6. Click **Add User**.

### 3. Allow network access

1. Atlas → **Network Access** → **Add IP Address**.
2. For development/testing: click **Allow Access from Anywhere** (`0.0.0.0/0`).
   - For tighter security later, add only Render's outbound IPs or use Atlas VPC peering on paid plans.
3. Click **Confirm**.

### 4. Get your connection string

1. Atlas → **Database** → **Connect** on your cluster.
2. Choose **Drivers** → Node.js → copy the connection string.
3. It looks like:

```
mongodb+srv://vetai360_user:<password>@vetai360-cluster.xxxxx.mongodb.net/?retryWrites=true&w=majority
```

4. Replace `<password>` with your actual password (URL-encode special characters like `@`, `#`, `%`).
5. Add the database name before the `?`:

```
mongodb+srv://vetai360_user:YOUR_PASSWORD@vetai360-cluster.xxxxx.mongodb.net/vetai360?retryWrites=true&w=majority
```

### 5. Test the connection locally

Copy `.env.production.example` to `backend/.env` and set your Atlas URI:

```powershell
# In backend/.env
DB_TYPE=mongo
MONGODB_URI=mongodb+srv://vetai360_user:YOUR_PASSWORD@cluster....mongodb.net/vetai360?retryWrites=true&w=majority
MONGO_DB_NAME=vetai360
```

Then verify and seed:

```powershell
npm run setup:atlas          # test connection
npm run setup:atlas:seed     # test + create demo accounts
```

You should see `✅ MongoDB Atlas connection successful!`

## Part 2 — Deploy to Render.com

Render hosts all three app services. MongoDB stays on Atlas.

### 1. Push code to GitHub

Render deploys from Git. If you haven't already:

```powershell
git init
git add .
git commit -m "VetAI 360 production deployment config"
git remote add origin https://github.com/YOUR_USERNAME/vetai360.git
git push -u origin main
```

### 2. Create a Render account

1. Go to [https://render.com](https://render.com) and sign up.
2. Connect your GitHub account.

### 3. Deploy with Blueprint (recommended)

1. Render Dashboard → **New** → **Blueprint**.
2. Connect your `vetai360` GitHub repository.
3. Render detects `render.yaml` and shows 3 services:
   - `vetai360-ml` — ML service
   - `vetai360-api` — Backend API
   - `vetai360-web` — Frontend
4. Click **Apply**.

### 4. Set MongoDB URI on the API service

After the blueprint is created:

1. Open the **vetai360-api** service in Render.
2. Go to **Environment** → find `MONGODB_URI`.
3. Paste your full Atlas connection string.
4. Click **Save Changes** — Render redeploys the API.

> `JWT_SECRET` is auto-generated by the blueprint. `SEED_ON_START=true` creates demo accounts on first boot.

### 5. Wait for all services to go live

First deploy takes **5–10 minutes** (ML Docker image trains models during build).

| Service | URL (example) |
|---------|---------------|
| Frontend | `https://vetai360-web.onrender.com` |
| API | `https://vetai360-api.onrender.com` |
| ML | `https://vetai360-ml.onrender.com` |

### 6. Verify deployment

1. Open `https://vetai360-api.onrender.com/api/health` — should show `"mongodb": "connected"`.
2. Open `https://vetai360-ml.onrender.com/health` — should show `"status": "ok"`.
3. Open `https://vetai360-web.onrender.com` — log in with:
   - Farmer: `farmer@vetai360.dev` / `farmer123`
   - Vet: `vet@vetai360.dev` / `vet123`
   - Admin: `admin@vetai360.dev` / `admin123`

## Part 3 — Alternative: VPS + Docker + Atlas

If you have a VPS (DigitalOcean, AWS EC2, etc.) with Docker installed:

```powershell
# 1. Copy and fill in production env
copy .env.production.example .env.prod
# Edit .env.prod — set MONGODB_URI, JWT_SECRET, CLIENT_ORIGIN, VITE_* URLs

# 2. Build and run
npm run docker:prod
```

This starts ML + backend + frontend on the VPS, using Atlas for the database.

## Environment variables reference

### Backend (`vetai360-api`)

| Variable | Required | Description |
|----------|----------|-------------|
| `MONGODB_URI` | Yes | Atlas connection string |
| `DB_TYPE` | Yes | `mongo` |
| `JWT_SECRET` | Yes | Long random string (auto-generated on Render) |
| `ML_SERVICE_URL` | Yes | ML service URL (auto-linked on Render) |
| `CLIENT_ORIGIN` | Yes | Frontend URL for CORS (auto-linked on Render) |
| `SEED_ON_START` | No | `true` to seed demo data on boot |
| `ALLOW_RENDER_ORIGINS` | No | `true` to allow `*.onrender.com` CORS |

### Frontend (`vetai360-web`)

| Variable | Required | Description |
|----------|----------|-------------|
| `VITE_BACKEND_URL` | Yes | API base URL without `/api` (auto-linked on Render) |

### ML service (`vetai360-ml`)

No env vars required. Models are trained during Docker build.

## Post-deployment checklist

- [ ] Change demo account passwords or disable `SEED_ON_START` after first deploy
- [ ] Set a strong `JWT_SECRET` (Render generates one automatically)
- [ ] Restrict Atlas IP whitelist from `0.0.0.0/0` to known IPs when possible
- [ ] Add a custom domain in Render (Settings → Custom Domains)
- [ ] Update `CLIENT_ORIGIN` if you add a custom domain

## Troubleshooting

### API health shows `"mongodb": "disconnected"`

- Check `MONGODB_URI` in Render environment variables.
- Verify Atlas **Network Access** allows connections (IP whitelist).
- Verify username/password — special chars must be URL-encoded in the connection string.

### "AI diagnosis service isn't reachable"

- Check `vetai360-ml` service is running on Render.
- Verify `ML_SERVICE_URL` on the API service points to the ML service URL (with `https://`).

### CORS / login fails from frontend

- Ensure `CLIENT_ORIGIN` on the API matches your frontend URL exactly (including `https://`).
- Set `ALLOW_RENDER_ORIGINS=true` on the API service.

### Render free tier spins down after inactivity

- First request after ~15 min idle takes 30–60 seconds (cold start).
- Upgrade to a paid plan for always-on services and WebSocket reliability.

### ML service build timeout

- First build trains ML models (~2–3 min). If it fails, redeploy — Render retries.
- Models are baked into the Docker image so subsequent starts are fast.

## Custom domain (optional)

1. Render → **vetai360-web** → Settings → **Custom Domains** → add `app.yourdomain.com`.
2. Render → **vetai360-api** → add `api.yourdomain.com`.
3. Update DNS CNAME records as Render instructs.
4. Update API env: `CLIENT_ORIGIN=https://app.yourdomain.com`
5. Redeploy frontend with `VITE_BACKEND_URL=https://api.yourdomain.com`.
